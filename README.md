   1. 카드 추가 수령 여부를 확인하는 로직에 대해서 사람들은 어떻게 처리했을지 궁금하다.
      1. 현재 depth2까지밖에 줄이는 방법밖에는 모르겠는데 어떻게 할 수 있을까?
         1. DrawCommand 인터페이스를 구현하고 구현체들을 반환하는 식으로 depth 1로 구현했다.
         2. Enum으로 만드는 방법도 있었지만 Enum 내부 코드가 너무 지저분해진다고 느꼈다. 익명함수를 써서 다른 구현방법을 적어놓는 방법이있었는데 이는 람다식을 써도 깔끔하지 못했다.
         3. 왜 depth를 2이하로 줄이기 어려웠던 이유를 먼저 생각해보자면,  
            현재 카드의 총합 상태를 묻는 작업이 while문으로 돌아가고, 이 안에서 'n'라고 입력이 들어왔을 때 break로 멈추고 있었기 때문이다.  
            1. 이를 depth 1로 줄이기 위해 DrawCommand 인터페이스를 활용하고 구현체를 반환했다.
               1. 구현체에서는 질의('y', 'n')에 따라 다른 행동하고 있다.
                  1. 근데 여전히 'n'이 입력으로 들어왔을때 while문을 멈추게 할 수 있을지 고민됐다.
                        1. boolean 지역변수를 활용해 반환값을 boolean을 받는다 + while문 조건으로 추가한다.
                        2. Player에 수령여부를 확인하는 변수를 만들고, canDraw메서드에 조건을 묶는다.
                           2번 방식이 외부에서 봤을 떈 더 깔끔해보이지만, game -> Player 찾아서 boolean 변수 바꿈 이라는게 Player의 불변도 깨지고, 별로라고 생각되었다.  
                           그래서 나는 1번 방식으로 구현했다.
